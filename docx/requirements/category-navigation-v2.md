# 分类导航与展示 — 精确需求规格 v2.0

> ⚠️ 此文档为权威需求来源。已有代码中与此文档不一致的部分视为 bug，需修正。

---

## R1 — 分类页面 Tab 栏

### R1.1 布局

每个分类页面顶部有**最多三层**固定宽度 Tab 栏：

```
┌──────────────────────────────────────────────────────────┐
│  分类名称（h1 标题）                                      │
│                                                          │
│  [全部/当前分类] [兄弟分类1] [兄弟分类2] [兄弟分类3] ...  │  ← L1 固定宽度
│                                                          │
│  [全部] [子分类1] [子分类2] [子分类3] ...                 │  ← L2 固定宽度（选择后出现）
│                                                          │
│  [全部] [子子分类1] [子子分类2] ...                       │  ← L3 固定宽度（选择后出现）
│──────────────────────────────────────────────────────────│
│  页面列表 ...                                             │
└──────────────────────────────────────────────────────────┘
```

### R1.2 固定宽度

- 每个 Tab 按钮宽度固定为 `min-width: 120px`，文字居中
- 多个 Tab 排列不伸缩，超出宽度自动换行
- 各级别 Tab 栏宽度一致（占满内容区宽度）

### R1.3 交互逻辑

| 操作 | 结果 |
|------|------|
| 进入分类页面（如"物品"） | 显示 L1 栏：`[全部(物品)] [武器] [药品] [杂物]` |
| 点击 L1 的"武器" | 在 L1 下方弹出 L2 栏：`[全部(武器)] [剑] [枪] [戟] [刀]` |
| 点击 L2 的"剑" | 在 L2 下方弹出 L3 栏：`[全部(剑)] [短剑] [长剑]` |
| 点击 L3 项或"全部" | 更新页面列表为该分类下的页面 |

### R1.4 不出现重复

- L1 栏只包含当前分类的同级分类（`parent.children`）
- L2 栏只包含选中分类的子分类（`target.children`）
- L3 栏只包含选中子分类的子分类
- 各级栏位的"全部"按钮指代其所属层级
- **禁止**同一分类名称出现在两个不同栏位中

### R1.5 选中态

- light 模式：选中项背景为 `color-mix(in srgb, var(--fg) 8%, transparent)`
- dark 模式：选中项背景为 `color-mix(in srgb, var(--fg) 14%, transparent)`

### R1.6 数据来源

- 当前分类详情：`getCategoryById(id)` — 扁平对象，不含 children
- 子分类数据：从 `categoryStore.categories` 树中通过递归查找获取
- 页面列表：`getPagesByCategory(selectedCategoryId, page, size)`

### R1.7 URL 与跳转

- 点击 L1 Tab → 更新 URL 为 `/category/{id}`，但**不触发完整页面导航**（同页过滤）
- 实现方式：`router.replace` 更新 URL + 本地状态驱动 Tab 和页面列表

## R2 — 管理员创建分类的三级约束

### R2.1 前端约束

- 创建表单的"父分类"选择器仅显示**深度 ≤ 2** 的分类
- 深度 = 3 的分类**不显示**在下拉选项中
- 若某分类深度 = 3，其"添加子分类"按钮置灰，提示"已达最大深度"

### R2.2 后端约束

- `CategoryService.createCategory()` 中：
  - 若 `request.parentId != null`，查询该父分类
  - 计算父分类深度：`getCategoryLevel(parent)`
  - 若深度 ≥ 3，抛出 `BusinessException("分类最多支持三级")`
  - 深度计算：根级 = 1，每有一层 parent 则 +1

## R3 — 删除分类与页面迁移

### R3.1 流程

```
管理员点击"删除分类"
  │
  ├─ 该分类有子分类？
  │   └─ 是 → 阻断：提示"请先删除子分类"
  │
  ├─ 该分类有页面（wiki_pages.category_id = 该分类 ID）？
  │   ├─ 是 → 弹出「迁移页面」对话框
  │   │       ├─ 显示被删分类名
  │   │       ├─ 下拉选择目标分类（排除自身及子孙）
  │   │       └─ 点"迁移并删除" → 后端迁移所有页面 → 删除分类
  │   └─ 否 → 直接删除
  │
  └─ 成功后刷新列表
```

### R3.2 后端接口

```
DELETE /api/categories/{id}?migrateTo={targetId}
```

- 若 `migrateTo` 为空且无页面 → 直接删除
- 若 `migrateTo` 非空 → `pageRepository.migratePagesToCategory(id, targetId)` → 删除分类
- 若 `migrateTo` 为空但有页面 → 仍可删除（页面 categoryId 变为 NULL，需后续处理）

### R3.3 错误处理

| 场景 | 处理 |
|------|------|
| 目标分类不存在 | 后端 400 "目标分类不存在" |
| 被删分类不存在 | 后端 400 "分类不存在" |
| 有子分类 | 后端 400 "请先删除子分类" |

## R4 — 管理员页面 UI 一致性

所有 `/admin/*` 页面必须：

| 元素 | 规范 |
|------|------|
| 页面标题 | `.eyebrow` + `.section-title` 组合 |
| 表格 | `el-table` 全局覆盖（dark 自动适配） |
| 按钮 | `.btn-primary` / `.btn-ghost` |
| 搜索框 | `.search-box` 容器 + `el-input` |
| 弹窗 | `el-dialog` 全局覆盖 |
| 分页 | `el-pagination` 全局覆盖 |
| 空状态 | `el-empty` 全局覆盖 |

所有交互必须有 `transition`（≥150ms）。
